# 주문 대화 규칙 (다시 짜기 전 정리)

주문 대화 부분(`kiosk/assistant/`, `kiosk/domain/flow.py`)을 다시 짜기 전에, 지켜야 할 규칙을
한 곳에 모은 문서예요. 지금까지의 구현, 팀 테스트 피드백, 새로 정한 방향을 합쳤어요.
결정이 필요했던 세 가지는 2026-10-26에 정했어요 (맨 아래).

## 0. 설계 원칙

1. **주문 상태는 코드 한 곳에만 있어요.** 담긴 메뉴, 고르는 중인 메뉴, **지금 묻는 질문**,
   지나온 화면 기록이 여기에 들어 있어요. 화면도 AI 지시도 이것만 봐요. 화면과 AI의 질문이
   어긋날 수 없게 하려는 거예요.
2. **규칙은 두 종류예요.**
   - **막는 규칙**: 되돌리기 어려운 것만 코드가 막아요 (결제 시작, 주문 전체 취소).
   - **받아들이고 보여 주는 규칙**: 나머지(메뉴, 옵션, 수량)는 AI가 이해한 대로 바로 반영해서
     화면에 보여 줘요. 틀린 건 손님이 화면이나 결제 전 주문 확인에서 바로잡아요.
3. **주문 진행 순서는 한 곳에 정의해요.** 매장/포장 → 메뉴 → 필수 옵션 → 추가 옵션 → 담기 →
   (다음 메뉴) → 직원 전달 질문 → 주문 확인 → 결제. 규칙을 추가할 때는 이 순서에 단계를
   더하는 식으로 해요.
4. **AI 함수는 적게 둬요.** 비슷한 함수를 묶어서 AI가 헷갈릴 일을 줄여요.
5. **팀 테스트 사례는 모두 자동 시나리오로 만들어요.** 새 코드는 시나리오를 다 통과해야 합쳐요.

## 1. 시작과 끝

- 수화기를 들면 시작해요. AI가 인사하고 **매장/포장**을 물어요. 화면에는 두 선택지가 떠요.
- 수화기를 내려놓으면 언제든 끝나고 주문은 모두 지워져요. 묻지 않아요.
- 결제가 끝나면 주문 번호를 알려 주고, 잠시 뒤 처음 화면으로 돌아가요.

## 2. 매장/포장

- 인사와 함께 물어요: "안녕하세요, ○○입니다. 매장에서 드시고 가세요, 포장하세요?"
- 답을 들으면: "메뉴판에서 메뉴를 고르신 뒤 말씀해 주세요." 화면에도 같은 문구가 떠요.
- 손님이 바로 주문부터 하면 주문을 받고, 매장/포장은 나중에 물어요.
- 결제할 때까지 모르면 다시 물어요. 화면에 선택지가 다시 떠요.
- "아메리카노는 포장, 라떼는 매장"처럼 섞이면 직원 전달 메모로 남겨요 (9번).

## 3. 메뉴 보여 주기

- 키오스크 옆에 **종이 메뉴판**이 있어요. 손님은 보통 거기서 고르고 말해요. AI는 메뉴를 길게
  읽지 않고 메뉴판을 가리켜요.
- "메뉴 뭐 있어요?": 추천 메뉴 3~5개를 화면에 띄우고 짧게 이름만 말해요. "전체 메뉴는 메뉴판에
  있어요"라고 덧붙여요.
- "다른 메뉴도요": 메뉴 종류(커피, 라떼, …)를 보여 줘요. 종류를 말하면 그 종류의 메뉴를 보여 줘요.
- 조건("우유 알레르기", "카페인 없는 거", "안 단 거"): 조건에 맞는 메뉴만 짧은 제목과 함께
  보여 줘요. **알레르기 거르기는 코드가 데이터로 해요.**
- 화면에는 한 번에 적게(최대 5개, 메뉴 종류 하나를 통째로 보여 줄 때는 예외) 띄워요. 모두 목록
  형태예요.

## 4. 메뉴 담기

1. 메뉴 이름을 들으면 바로 담기 시작해요. 손님이 같이 말한 옵션과 수량도 함께요. 수량을 말하지
   않았으면 1이에요.
2. **필수 옵션(온도, 사이즈)은 하나씩** 물어요. 그 메뉴에 있는 것만, 순서는 코드가 정해요.
   **지금 묻는 질문은 코드의 "현재 질문"이고, 화면과 AI가 둘 다 이것을 따라요.**
   - 묻는 말은 짧게, 선택지와 가격은 읽지 않아요: "사이즈는 어떤 걸로 해 드릴까요?"
   - 온도는 "따뜻하게 드릴까요, 차갑게 드릴까요?"처럼 물어요.
   - 한 가지로만 나오는 메뉴(아이스만, 한 사이즈)는 그 옵션을 묻지 않아요.
   - 손님이 한 번에 여러 개를 말하면("차갑게 라지로") 한꺼번에 반영하고 다음 질문으로 넘어가요.
3. **추가 옵션**(샷, 시럽, 텀블러, 토핑)은 **주문의 첫 메뉴에서만** 물어요. 필수 옵션이 다
   정해지면 화면에 목록으로 띄우고 "추가하실 거 있으세요?" 하고 물어요. 목록은 읽지 않아요.
   원하는 걸 반영한 뒤 "더 추가하실 거 있으세요?" 하고, "없어요"라고 하면 담기 완료예요.
   - 두 번째 메뉴부터는 묻지 않고, 필수 옵션이 정해지면 바로 담아요. 손님이 먼저 말하면("샷
     추가해 주세요") 반영해요.
   - 추가 옵션이 없는 메뉴는 첫 메뉴라도 바로 담아요.
4. 담기면 짧게 알리고 "더 필요하신 거 있으세요?"라고 물어요.
5. 이미 고른 옵션은 화면에 작은 표시(칩)로 남아요.
6. **여러 메뉴를 한 번에** ("라떼 하나랑 아메리카노 하나"): 각각 담기 시작해서 하나씩 질문을
   이어 가요. 화면에는 지금 묻는 메뉴가 떠요.
7. **같은 메뉴를 나눠서** ("아메리카노 세 잔, 하나는 차갑게 두 잔은 따뜻하게"): 나뉜 만큼 따로
   담기고, 각각 따로 주문 줄이 돼요. "둘 다 라지요" 같은 답은 둘 모두에 적용돼요.
   - **답이 어느 잔인지 모호하면 확인해요** (2026-10-27 팀 테스트: "아이스/핫 아메리카노"를 한 번에
     주문하고 "레귤러요"라고 하자 두 잔 모두에 들어감). 같은 메뉴가 둘 이상이고 손님이 어느 잔인지나
     "둘 다"를 말하지 않으면, 답은 **지금 묻는 잔에만** 들어가고 "따뜻한 아메리카노도 레귤러로 해
     드릴까요?" 하고 물어요. "네"면 그 잔에도 넣어요. "아니요"면 선택지가 두 개뿐인 옵션(사이즈,
     온도)은 **남은 하나**로 정하고(라지가 아니면 레귤러), 셋 이상이면 그 잔의 옵션을 따로 물어요.
   - **묶음 중 일부만** ("따뜻한 아메리카노 두 잔" 중 "하나만 라지로"): "세 잔 중 둘은 따뜻하게"와
     똑같이 그 잔 수만큼 떼어서 따로 담고, 남은 잔은 다시 물어요. 손님이 잔을 정해서 말한 것이라
     확인 질문은 하지 않아요. AI가 묶음 번호를 잘못 짚어도(방금 따뜻하게 만든 묶음에 "나머지는
     차갑게"), 아직 그 옵션이 없는 묶음으로 가요.
   - 이렇게 나뉜 잔들은 추가 옵션을 한 번만 물어요. "없어요" 한 번이면 모두 담겨요.
   - **추가 옵션도 똑같이 확인해요**: 나뉜 잔들이 추가 옵션 질문을 받는 중에 "샷 추가해 줘"라고만
     하면 묻는 잔에만 넣고 "차가운 레귤러 아메리카노에도 샷 추가 해 드릴까요?" 하고 물어요. "아니"면
     그 잔에는 넣지 않아요. "둘 다 / 셋 다 / 세 잔 다 / 전부"면 확인 없이 모두에 넣어요.
     **이미 주문에 담긴 같은 메뉴**도 확인해요 ("아이스 하나, 핫 하나"는 핫이 사이즈가 정해지자마자
     담겨요): "따뜻한 레귤러 아메리카노에도 샷 추가 해 드릴까요?" → "응"이면 그 주문 줄을 고쳐요.
   - 질문을 처음부터 "차가운 아메리카노 사이즈는…"처럼 자세히 하거나 질문 순서를 바꾸지는 않아요.
   - 손님이 "둘 다/전부/똑같이"라고 하지 않았는데 AI가 같은 답을 두 잔에 넣으면, 코드가 두 번째
     잔에는 넣지 않고 같은 확인 질문을 해요.
8. **필수 옵션을 AI가 짐작해서 정하면 안 돼요.** "손님이 그 선택지를 말했는지" 코드가 문장으로
   검사해서 막던 규칙은 **없앴어요.** 이 검사가 "라지요 → 라디오"처럼 잘못 알아들은 경우와 검사
   범위 문제로 같은 질문을 반복하게 만들었어요.
   - **화면이 묻고 있는 질문에 대한 답은 어떤 말이든 그대로 받아요.** 그래서 같은 질문을 두 번
     하지 않아요.
   - 대신 짐작만 막아요 (2026-10-26 실제 음성 시나리오에서 추가): 손님이 그 옵션을 **아예 말하지
     않았고** 화면도 그걸 묻고 있지 않은데 AI가 넣으면("아메리카노 세 잔, 하나는 차갑게…"에
     레귤러, "카페라떼 하나요"에 차갑게) 넣지 않고 키오스크가 물어요. "말했는지"는 옵션마다 정한
     단어(`menu.yaml`의 `words`: 사이즈·레귤러·라지·큰…)로 봐요.

## 5. 주문 고치기

- "라떼는 라지로 바꿔 주세요": 바로 바꾸고, 바뀐 옵션 화면을 보여 줘요. 새 선택이 표시된 채로요.
- "쿠키는 빼 주세요": 그 줄을 빼요. "하나 더요": 수량을 바꿔요.
- 메뉴를 다른 걸로 바꾸려면 빼고 새로 담아요.
- 바꾸면 결제 준비(주문 확인)는 처음부터 다시 해요.

## 6. 뒤로가기 (하나로 통일)

- 지나온 **모든 화면**이 기록돼요: 메뉴 목록, 메뉴 종류, 옵션 질문 하나하나, 주문 내역, 안내 카드.
- "뒤로", "이전 화면": 바로 전 화면으로 가요. 사이즈 질문에서 뒤로 가면 온도 질문이 다시 떠요.
- "아까 라떼 화면 보여 주세요"처럼 특정 화면을 말하면 그 화면까지 한 번에 돌아가요.
- **뒤로가기는 화면만 바꾸고 주문은 바꾸지 않아요.** 이미 고른 옵션은 표시된 채로 남아요. 바꾸고
  싶다고 하면 그때 바꿔요 (5번).
- 이미 담은 메뉴의 화면으로 돌아가면, 그 메뉴의 지금 옵션이 보이고 거기서 바로 바꿀 수 있어요.
  지금 따로 있는 "주문한 메뉴 옵션 다시 보기"(`edit_line`)는 이걸로 대신해요.
- 결제 화면(카드 단말기, 주문 번호)은 뒤로가기 대상이 아니에요. 결제 중 "취소"는 7번 규칙을 따라요.

## 7. 결제 (막는 규칙)

1. **손님이 결제를 원한다고 말했을 때만** 시작해요: "결제할게요", "계산이요", 또는 "더 필요하신
   거 있으세요?"에 "없어요". 코드가 손님의 말로 확인해요.
   - "추가하실 거 있으세요?"(추가 옵션 질문)에 "없어요"는 결제 요청이 **아니에요**.
   - 주문이 바뀌면 다시 결제를 요청해야 해요.
2. 담는 중인 메뉴가 없어야 하고, 매장/포장이 정해져 있어야 해요.
3. 처음 한 번은 **"직원에게 따로 전달할 말씀 있으세요?"**를 물어요. 이때 화면에는 주문 내역이
   떠요.
4. 그다음 **주문 확인**: 코드가 쓴 문장을 그대로 읽어요 ("주문 확인해 드릴게요. … 총 ○원입니다").
   질문이 아니라 확인이에요. 카드 이야기는 아직 하지 않아요.
5. 다 읽으면 화면에 카드 단말기가 뜨고, AI가 "카드를 단말기에 꽂아 주세요"라고 해요 (모의 결제).
6. 주문 확인 중에 손님이 끼어들면: "네"는 진행, "잠깐만요"나 "취소"는 결제 중단, 그 밖의 말은
   AI의 다음 대답을 기다려요.
7. 결제 완료: 주문 번호와 받는 곳을 알려 주고, 수화기를 내려놓아도 된다고 해요.

## 8. 주문 전체 취소 (막는 규칙)

- 손님이 전부 취소하려고 하면 "주문을 모두 취소할까요?"라고 묻고, **"네"라고 했을 때만** 취소해요.
  코드가 확인해요.
- 메뉴 하나만 빼는 건 5번이에요.

## 9. 키오스크가 못 하는 요청 (직원 전달)

- 만드는 법이나 내주는 법에 관한 요청("얼음 적게", "아메리카노는 포장, 라떼는 매장", "컵 따로")은
  **불가능하다고 하지 않아요.** 메모로 남기고 "네, 알겠습니다. 해당 사항은 직원에게
  전달하겠습니다."라고 해요.
- 메모는 주문 확인 화면과 주문 번호 화면에 크게 보여요.
- 메뉴에 없는 메뉴나 옵션은 주문할 수 없다고 말해요.

## 10. 질문에 답하기

- 메뉴와 카페 정보 질문은 **데이터에 있는 것만** 답해요. 데이터에 없으면 모른다고 하고 직원에게
  물어보라고 해요. 지어내지 않아요.
- 메뉴 설명은 화면에 쓰지 않고 AI가 말로 해요. 화면에는 사진, 재료, 알레르기 같은 정보만 보여 줘요.
- 알레르기 질문에는 "알레르기 정보는 참고용이니 직원에게 꼭 확인해 주세요"라고 덧붙여요.
- 카페 정보(화장실, 와이파이, …)는 안내 카드로 보여 줘요. 결제 후에도 볼 수 있어요.

## 11. 말하는 방식

- 해요체, 친절하게. 빠르고 짧게: 가능하면 한 문장, 많아야 두 문장이에요.
- 온도는 항상 "따뜻하게 / 차갑게" ("따뜻한 / 차가운 아메리카노")로 말해요. 아이스, 핫은 쓰지 않아요.
- 선택지, 가격, 긴 목록은 읽지 않아요. 화면과 메뉴판이 보여 줘요.
- 함수, 시스템, 데이터 같은 말은 하지 않아요. 가격은 한국식으로 읽어요 ("사천오백 원").
  AI에게는 가격을 한글로 줘요 ("만 삼천이백 원"): 숫자("13,200원")로 주면 "십삼만 이천 원"처럼
  10배로 읽은 적이 있어요 (2026-10-27 팀 테스트). 화면은 숫자 그대로예요.
- 화면에 띄운 것에 대해서만 말해요. 메뉴를 말할 때는 먼저 화면에 띄워요.

## 12. 듣기

- **고민하는 소리**("어…", "음…", "그…", "잠깐만요", "뭐 먹지…")에는 대답하지 않고 기다려요. AI가
  "조용히 기다리기"를 고르면 코드가 그 차례를 무음으로 만들어요. 판단은 소리를 직접 듣는 AI가 하고,
  코드가 단어만 보고 무시하지는 않아요. 오래 조용해도 먼저 말을 걸지 않아요.
- **키오스크에 하는 말이 아닌 소리**(옆 사람, 통화): F2 스위치를 켰을 때만 무시해요. 무시한 말은
  결제 요청 같은 판단에도 쓰지 않아요.
- 잘 못 알아들었으면 짧게 다시 물어요. 알아들은 척 넘어가지 않아요.
- 손님이 AI 말 중간에 끼어들면 바로 멈추고 손님 말을 들어요.
- 문장 중간에 조금 쉬어도 끝난 것으로 치지 않아요 (음성 감지 설정).

## 13. 화면

- 아바타가 뒤에 서 있고, 지금 묻는 것만 아바타 가슴 위에 목록으로 보여요.
- 이미 고른 옵션은 칩으로, 직원 전달 메모는 크게 보여요.
- 자막은 기본으로 꺼져 있고 F2에서 켤 수 있어요.

## 14. 연결이 끊기면

- 손님에게 연결 이야기는 하지 않고 대화를 이어 가요. 새 연결에는 지금까지의 주문, 고르는 중인
  메뉴, 최근 대화를 넘겨 줘요.

## 15. 자동 시나리오로 만들 팀 테스트 사례

`uv run python scripts/voice_demo.py --scenario all`로 실제 Live API에서 돌려요 (`--scenario list`로
목록 보기). 코드만 확인하는 부분은 `tests/test_conversation_rules.py`에 있어요.

| 사례 | 기대 결과 |
|---|---|
| 매장/포장 답한 뒤 | "메뉴판에서 메뉴를 고르신 뒤 말씀해 주세요" |

| 사이즈 질문 | 선택지와 가격을 읽지 않음 |
| "아메리카노 세 잔, 하나는 차갑게 두 잔은 따뜻하게" | 차가운 1잔, 따뜻한 2잔이 따로 담김 |
| "라지요"가 "라디오"로 인식됨 | 사이즈가 정해지고 다시 묻지 않음 |
| 온도를 말했는데 AI가 기록을 빠뜨림 (18:05 로그) | 같은 질문을 반복하지 않고, 화면과 질문이 일치함 |
| "아메리카노는 얼음 조금만 넣어 주세요" (중간에 쉼) | 한 문장으로 들리고 직원 메모가 됨 |
| "아메리카노는 포장, 라떼는 매장" | 직원 메모가 되고 거절하지 않음 |
| 친구와의 대화, 통화 (F2 스위치 켬) | 대답하지 않음 |
| "음…", "어…" 뒤에 "아메리카노요" | 고민 소리에는 조용하고, 주문은 받음 |
| "추가하실 거 있으세요?"에 "없어요" | 결제가 시작되지 않음 |
| 두 번째 메뉴 | 추가 옵션을 묻지 않고 바로 담김 |
| "아이스 아메리카노 하나랑 핫 아메리카노 하나" → "레귤러요" | 묻는 잔에만 들어가고 "따뜻한 아메리카노도 레귤러로 해 드릴까요?" ("네" / "아니요" 둘 다) |
| 위와 같은 주문 → "둘 다 레귤러요" / "아이스는 레귤러, 핫은 라지" | 확인 없이 말한 대로 들어감 |
| 확인 질문 "…도 라지로 해 드릴까요?"에 "아니" | 다시 묻지 않고 레귤러 |
| 3잔을 나눈 뒤 추가 옵션 질문에 "샷추가 해줘" | 묻는 잔에만 넣고 "…에도 샷 추가 해 드릴까요?" 확인 ("응" / "아니") |
| "셋 다 레귤러로" | 확인 없이 모두 레귤러 |
| "아이스 하나랑 핫 하나" → "둘 다 레귤러요" → (아이스의 추가 옵션에) "샷추가 해줘" | 이미 담긴 핫도 "…에도 샷 추가 해 드릴까요?" 확인 ("응" / "아니") |
| "아메리카노 3개" → "2개는 따듯하게, 나머지는 차갑게" → (따뜻한 2잔에) "하나만 라지로" | 따뜻한 라지 1잔이 따로 담기고 남은 1잔의 사이즈를 물음; 추가 옵션은 한 번만 물음 |
| 결제 전 주문 확인의 합계 | 화면 가격대로 읽음 (13,200원 → "만 삼천이백 원") |
| "더 추가하실 메뉴 있으세요?"에 "없어" | 결제로 넘어감 (직원 질문부터) |
| 사이즈 질문에서 "뒤로" | 온도 질문이 다시 뜨고 고른 온도는 남아 있음 |
| 담은 라떼 화면으로 돌아가 "라지로 바꿔 주세요" | 라떼가 라지로 바뀜 |
| 주문 확인 중 "네" / "잠깐만요" | 결제 진행 / 결제 중단 |
| "전부 취소해 주세요" → "네" | 주문 전체 취소 |

## 정한 것 (2026-10-26)

1. 필수 옵션 문장 검사: **없애요.** 화면과 결제 전 주문 확인으로 바로잡아요.
2. 오래 조용할 때 먼저 말 걸기: **하지 않아요.**
3. 추가 옵션 질문: **주문의 첫 메뉴에서만** 물어요.
