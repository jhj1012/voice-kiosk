# 주문 대화 다시 짜기: 설계

[주문 대화 규칙](conversation-rules.md)을 지키는 새 구조예요. 2026-10-26에 확인받았어요.

## 1. 무엇을 바꾸고 무엇을 남기나

| 부분 | 어떻게 |
|---|---|
| 메뉴·카페 데이터, 주문 금액 계산 (`domain/menu.py`, `order.py`, `loader.py`) | **남겨요.** 문제가 없어요. |
| 주문 진행 (`domain/flow.py`) | **새로 짜요.** "현재 질문"과 화면 기록을 중심으로 해요. |
| AI 함수와 결과 (`assistant/tools.py`, `actions.py`) | **새로 짜요.** 함수 17개를 11개로 줄여요. |
| 안전 규칙 (`assistant/safety.py`) | **줄여요.** 결제 요청과 전체 취소 확인만 남겨요. 옵션 문장 검사, 메뉴 언급 위치 찾기, 비슷한 글자 비교는 없애요. |
| 대화 세션 (`assistant/session.py`) | **정리해요.** 연결, 오디오, 끼어들기, 결제 진행은 그대로 쓰고, 함수 처리 부분만 단순하게 바꿔요. |
| AI 지시문 (`assistant/instructions.py`) | **새로 써요.** 규칙 문서의 순서대로요. |
| 화면 (`frontend/`) | **조금 바꿔요.** "현재 질문"을 그대로 그리게 해요. 디자인은 그대로예요. |
| 서버, 수화기, 설정, 런처, API 키 | **그대로예요.** |

## 2. 핵심: 주문 상태와 "현재 질문"

코드가 주문 상태를 하나만 갖고, 화면과 AI는 둘 다 이걸 봐요.

```
주문 상태
├─ 매장/포장, 직원 전달 메모
├─ 담긴 줄들        (아메리카노 차갑게 라지 1잔, …)
├─ 고르는 중인 메뉴 (각각 번호가 있어요: #1 카페라떼 따뜻하게 ?사이즈)
├─ 현재 질문         ← 화면에 보이는 것 = AI가 물어야 하는 것
└─ 화면 기록         ← 뒤로가기
```

**현재 질문**은 코드가 정해요. 종류는 이래요:

| 질문 | 언제 | 화면 | AI가 묻는 말 (코드가 정해 줘요) |
|---|---|---|---|
| 매장/포장 | 처음, 또는 결제할 때까지 모르면 | 두 줄 목록 | "매장에서 드시고 가세요, 포장하세요?" |
| 메뉴 고르기 | 매장/포장 뒤, 메뉴를 담은 뒤 | 메뉴판 안내, 또는 AI가 띄운 메뉴 | "메뉴판에서 메뉴를 고르신 뒤 말씀해 주세요." / "더 필요하신 거 있으세요?" |
| 필수 옵션 | 고르는 중인 메뉴에 빠진 옵션이 있을 때 | 그 옵션의 선택지만 | "사이즈는 어떤 걸로 해 드릴까요?" / "따뜻하게 드릴까요, 차갑게 드릴까요?" |
| 추가 옵션 | 주문의 **첫 메뉴**에서 필수 옵션이 다 정해졌을 때 | 추가 옵션 목록 | "추가하실 거 있으세요?" |
| 직원 전달 | 결제를 요청했을 때 처음 한 번 | 주문 내역 | "직원에게 따로 전달할 말씀 있으세요?" |
| 주문 확인 | 그다음 | 주문 내역 | 코드가 쓴 확인 문장 그대로 |
| (결제) | 확인을 다 읽은 뒤 | 카드 단말기 → 주문 번호 | "카드를 단말기에 꽂아 주세요" → 번호와 받는 곳 |

- 모든 함수의 결과에는 **다음 질문**이 들어 있어요. 질문 종류, AI가 할 말, 화면에 무엇이 보이는지요.
  AI는 그 말을 해요. 화면은 같은 질문을 그리고요. 그래서 둘이 어긋날 수 없어요.
- 고르는 중인 메뉴가 여럿이면 질문은 하나씩 이어져요. "라떼 사이즈" → "아메리카노 사이즈" 순서예요.
- 손님이 묻지 않은 걸 먼저 말해도("차갑게 라지로") 다 반영하고, 남은 것만 물어요.

### 18:05 로그 같은 경우는 이렇게 돼요

- **옵션 문장 검사가 없어요.** AI가 늦게 보낸 "따뜻하게"도 그대로 받아요. 그래서 같은 질문이
  반복되지 않아요.
- AI가 기록을 아예 빠뜨리면, 화면은 여전히 "온도"를 보여 주고 결과도 "온도를 물으세요"라고 해요.
  AI가 다른 질문(사이즈)을 해도 손님 눈에는 온도 선택지가 보여요. 손님이 답하면 AI가 그때 기록해요.
- 그래도 어긋날 수 있는 이 마지막 틈은 지시문으로 줄여요: "손님이 답하면 말하기 전에 반드시
  answer를 부르세요". 실제로 얼마나 줄었는지는 시나리오로 재요.

## 3. AI 함수: 17개 → 11개

함수는 **무엇을 바꾸는지**로 나눠요. **어떤 질문에 대한 답인지**로 나누지 않아요. 손님은 AI가 묻지
않은 것까지 한 번에 말할 수 있어요 ("아메리카노 아이스로, 그리고 카페라떼는 따뜻한 걸로 주세요").
그런 말은 한 차례에 함수 여러 개로 처리해요. AI는 한 번에 여러 함수를 부를 수 있고, 지금도 그렇게
하고 있어요. **현재 질문은 함수를 묶지 않아요.** 함수들이 실행된 뒤 코드가 아직 빠진 것을 보고 다음
질문을 정하는 데만 써요.

| 새 함수 | 하는 일 | 바뀌는 지금 함수 |
|---|---|---|
| `show(what, …)` | 화면 띄우기: 메뉴(추천·종류·조건·알레르기 거르기), 메뉴 종류, 메뉴 하나, 카페 정보, 주문 내역 | show_menu, show_categories, show_item, show_info, show_order |
| `order(item, quantity?, options…)` | 새 메뉴 담기 시작. 같은 메뉴를 나누면("세 잔 중 하나는 차갑게") 부를 때마다 따로 생겨요 | choose_item |
| `set_options(item, options…, quantity?, draft?)` | 고르는 중인 메뉴의 옵션과 수량. 같은 메뉴가 여럿이면 옵션이 맞는 쪽으로 가요. 수량 0이면 그 메뉴를 취소해요 | set_options, cancel_item |
| `no_more_extras(item?)` | "추가하실 거 있으세요?"에 "없어요": 그 메뉴를 담아요 | finish_item |
| `set_dining(dining)` | 매장/포장 | (같아요) |
| `change(line, quantity?, options…)` | 이미 담긴 줄 바꾸기. 수량 0이면 빼기 | change_line |
| `go_back(to?)` | 뒤로가기. `to`가 없으면 한 화면, "카페라떼"처럼 주면 그 화면까지 | go_back, edit_line |
| `note_for_staff(text)` | 직원 전달 메모 | (같아요) |
| `pay()` | 결제 요청. 코드가 결제 의사를 확인하고, 직원 전달 질문 → 주문 확인 순서로 이어 가요 | request_payment |
| `cancel_order()` | 주문 전체 취소. "네"를 확인해요 | cancel_order, cancel_payment |
| `stay_quiet()` | 고민 소리("음…")나 키오스크에 하는 말이 아닐 때 대답하지 않기 | stay_quiet (F2 스위치를 켰을 때만 있던 것) |

예시:

| 손님 | 상황 | 함수 |
|---|---|---|
| "아메리카노 아이스로, 그리고 카페라떼는 따뜻한 걸로 주세요" | 처음 | `order(americano, ice)` + `order(cafe_latte, hot)` → 다음 질문: 아메리카노 사이즈 |
| 같은 말 | 둘 다 고르는 중 | `set_options(americano, ice)` + `set_options(cafe_latte, hot)` |
| "둘 다 라지요" | 둘 다 사이즈가 빠짐 | `set_options(americano, large)` + `set_options(cafe_latte, large)` |
| "라떼는 차갑게요" | 화면에는 아메리카노 사이즈 질문 | `set_options(cafe_latte, ice)` → 질문은 아메리카노 사이즈 그대로 |
| "포장이요, 아이스 아메리카노 하나요" | 처음 | `set_dining(to_go)` + `order(americano, ice)` |

옵션 인자는 지금처럼 평평한 값이에요 (`temperature`, `size`, `shot` …). 모델이 가장 잘 채웠던
형태예요.

## 4. 막는 규칙과 받아들이는 규칙

| 규칙 | 어디서 | 방식 |
|---|---|---|
| 결제는 손님이 요청했을 때만 | `pay()` | **막아요.** 손님 말로 확인해요. 추가 옵션 질문에 한 "없어요"는 요청이 아니에요. |
| 결제 전에 주문 확인을 끝까지 읽기 | 세션 | **막아요.** 다 읽은 뒤에 카드 단말기가 떠요. 끼어들기 규칙은 지금과 같아요. |
| 결제 전 직원 전달 질문 한 번 | `pay()` | 코드가 순서로 정해요 |
| 주문이 바뀌면 결제를 다시 요청해야 해요 | `pay()` | **막아요** |
| 전체 취소는 "네"를 들은 뒤에만 | `cancel_order()` | **막아요** |
| 필수 옵션은 짐작하지 않기 | 지시문 + 세션 | 화면이 묻는 질문의 답은 그대로 받아요. 아예 말하지 않은 옵션(짐작)만 넣지 않고 물어요. |
| 메뉴에 없는 메뉴·옵션 | 코드 | 받아들이지 않고 오류로 알려 줘요 (데이터에 없으니까요) |
| 알레르기 거르기 | 코드 | 데이터로 해요 (지금과 같아요) |

## 5. 뒤로가기

- 화면이 바뀔 때마다 기록에 남아요. 기록에는 화면 종류, 메뉴, **현재 질문**이 함께 저장돼요.
  사이즈 질문 → 온도 질문처럼 같은 메뉴의 질문 사이도 따로 기록돼요.
- `go_back()`: 바로 전 기록으로 가요. `go_back(to="카페라떼")`: 기록을 거슬러 그 메뉴의 화면까지
  가요.
- 되돌아간 화면은 **지금 주문 상태로 다시 그려요.** 온도 질문으로 돌아가도 이미 고른 "차갑게"는
  표시돼요. 그 메뉴가 이미 담겼으면 그 줄의 지금 옵션이 보여요.
- 뒤로가기로 현재 질문이 그 화면의 질문으로 바뀌어요. 손님이 거기서 답하면("따뜻하게요") 그 답이
  반영돼요. 그다음 질문은 다시 코드가 정해요 (빠진 옵션이 없으면 원래 하던 곳으로 돌아가요).
- 결제 화면은 기록에 남지 않아요.

## 6. 듣기

- `stay_quiet()`는 항상 있어요. 고민 소리에는 AI가 이걸 부르고, 세션은 그 차례를 무음으로 만들어요.
  그 말은 결제 요청 같은 판단에도 쓰지 않아요 (지금 F2 스위치와 같은 방식이에요).
- F2 스위치("키오스크에 하는 말이 아니면 대답하지 않기")는 그대로예요. 켜면 옆 사람과의 대화도
  같은 방식으로 무시해요.
- 음성 감지 설정(짧게 쉬어도 끝난 것으로 치지 않기)은 그대로예요.

## 7. 화면이 받는 정보

`state` 이벤트의 `view`와 `pending` 자리에 **`question`**이 들어가요.

```jsonc
"question": {
  "kind": "option",            // dining | menu | option | extras | staff | review | payment | done
  "draft": 2,                  // 고르는 중인 메뉴 번호 (옵션·추가 옵션 질문일 때)
  "item_id": "cafe_latte",
  "group": "size",             // 옵션 질문일 때
  "line": 0,                   // 담긴 줄의 옵션을 보여 줄 때 (뒤로가기로 돌아갔을 때)
  "chosen": {"temperature": ["ice"]},
  "quantity": 1
}
```

화면은 `question`만 보고 그려요. 메뉴 목록, 정보 카드, 주문 내역처럼 AI가 띄운 화면은 지금처럼
`view`로 와요. 이때 `question`은 "메뉴 고르기"예요.

## 8. 작업 순서

1. `domain/flow.py`를 새로 짜요: 주문 상태, 현재 질문, 화면 기록. 순수 Python이고 테스트를 먼저
   써요.
2. 함수 11개와 결과 형식(`tools.py`, `actions.py`)
3. 세션 정리: `stay_quiet` 항상, 안전 규칙은 결제와 취소만
4. 지시문을 새로 써요
5. 화면이 `question`을 그리게 해요. 데모 녹화(`?demo=`)도 새로 만들어요.
6. 확인
   - `tests/test_conversation_rules.py`: 지금 실패로 표시된 5개를 포함해 **모두 통과**
   - `scripts/voice_demo.py --scenario all`: 실제 Live API에서 **13개 모두 통과**
   - 같은 시나리오로 지금 버전(main)과 새 버전을 비교한 표를 PR에 올려요: 통과 수, 응답 시간,
     같은 질문 반복 횟수, 아이스·핫이라고 말한 횟수
7. 문서(`architecture.md`, `decisions.md`) 정리, PR 하나로 올려요. 커밋은 단계별로 나눠요.

바뀐 함수에 묶인 테스트는 새 함수에 맞게 다시 써요. 규칙이 그대로인 것(결제, 취소, 연결 복구,
오디오, 끼어들기)은 내용을 유지하고 호출만 바꿔요 (2026-10-26 확인).
